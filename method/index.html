Your evening, and what is left of it

You ask an agent for a feature after dinner. By bedtime it has written more code than you will read this week. You still want to know what it does, and that it does only that. So you read three short pages, and the rest checks the code.

Three pages a part

How it works, what it promises, how you check each promise by hand.

A gate

One script runs every test and checks the pages against the code. Green or red. Nothing merges red.

Rules the tool applies

Lists and hooks, written once in files. Claude Code runs them on every call, so the agent cannot skip them.

A day with it

  1. 1
    You type /lorisse. The agent reads its memory and the project, says where things stand in five lines, and waits.
  2. 2
    You say what you want, in a line. The promise is written first, in the pages. You read those.
  3. 3
    A builder runs in its own branch, one part, and commits only on green.
  4. 4
    You read, note and mark the pages that changed, and walk the validation.
  5. 5
    You merge, or not. The main branch moves on your word only.

How to start

  1. 1
    Install Claude Code and sign in.
  2. 2
    Make your own copy. On GitHub, Use this template on lorisse-kit makes your private repository. Clone it, then run its install script once: the lint runs first, and a finding installs nothing.
  3. 3
    Type /lorisse in the kit's example project. Five lines, no question.

What it is not

×
Not a framework. Files, a few PowerShell scripts, and the habits they enforce.
×
Not a way to skip review. You review promises and walk steps instead of reading diffs.
×
Not a sandbox. The rules cut the prompts and refuse the risky calls. What runs on your machine is still yours to judge.
×
Not for every system. Windows and Windows PowerShell 5.1 only.
