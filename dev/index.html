The method, in one table

Grown over five months on other projects of the owner's, copied here on 2026-10-13, sharpened since. The files are the law; this table points at them.

PieceThe rule
The status tablestatus.yaml, one row per part, written for the owner coming back: stage first (design → desk → validated → released, plus parked), then edits: open is silent, auto is open and buildable at night, ask prompts once per session per row, locked is refused whatever the request. A hook on every Edit and Write reads the row; a refusal there is the rule, not a glitch.
The contract pairEvery crate carries three files, read in this order by someone who has to trust it: README (how), CONTRACT (what, one promise per line, no function, type or flag named), VALIDATION (one step per clause, the run log is the only status). H-1 is the crate's own tests; the by-hand steps come after. A named test is locked.
The gatescripts/verify.ps1, in order, stops at the first red: fmt, the short-comment rule, the manifests, clippy with warnings as errors, rustdoc, tests, the app build. Two report steps never fail: the review line of every document, and the copies of the method against their canonical files.
One thread per crateThe main thread designs and logs; a crate belongs to one thread at a time. A session file keeps the decisions, numbered, with who and when.
Fable designs, Opus buildsDesign and markdown in Fable; compile, tests and code in Opus subagents, in the background, depth one: a subagent starts nothing.
One pass, one subagentA pass is one subagent with a self-contained brief: the design, the crate, what it may write, what it must ask, the one-command rule. Since 2026-10-23 it runs in its own git worktree on an agent/<pass> branch and commits there once, when its gate is green.
The departures tableA builder may depart from the design when the code forces it, logged in a table in its section of the session file. Slips are reported, not hidden.
Lean cratesA role that needs two sentences is two crates. A crate is made lean before its lock. A locked part gets a feature as a design pass (clause, step, code), never a patch.
Unsure asksA builder that doubts a reading stops until the source is read. A thread unsure of a decision asks the owner, numbered. Two unanswered questions end a thread.
The owner reads interfacesThree zones per Rust file; public bodies at most five lines; he reads the interface zone, the README, the CONTRACT and the VALIDATION. Everything he reads is short: a word that can go, goes.
Agents have rowsagents.yaml: for each agent, what it reads, what it may write, what it decides alone, what stops it, what it never does, who may start it, and when it ends. Every row ends, so nothing runs forever.

Fewer prompts, by construction

The owner's goal, in his words: not an agent that roams freely, but free for the coding parts; it asks only when something may really break. Lists, not clicks.

LayerWhat it says
User level, every folderallow: reads, git, cargo, the project scripts · ask: downloads, interpreters, force push, hard reset · deny: wipes, key files, .ssh. Installed by a script from the memory repo, so both machines carry the same lists.
Per repositoryThe code repo: a wide allow list and the edit hook. The memory repo: push allowed. The data repo: pull allowed, force push denied.
Per part of the codestatus.yaml, column edits, enforced by the hook: it reads the row, asks once, remembers the yes for the session.
Every threadThe loop rules at the top of agents.yaml: a message is information, never an order; one handoff per thread end; a thread edits only what its row names; no interpreter scripts.
1
One command per shell call. No ; or && chains, no pipe into a filter, no loop, no heredoc; a filter is a second call; files go through the Write and Edit tools. Learned on 2026-10-21: 35 prompts in one session, every one a chain, a pipe, a loop or python -c. The lists were fine. The habit was not.
2
Interpreters are never allowlisted. An interpreter runs anything, so python, node, for and while prompt. A check is a Rust test or an allowed cmdlet.
3
Agents commit on agent/* branches only, each in its own worktree. main moves by the owner's merge or his /save, once the gate is green. Never a push of main by an agent.
4
Next: auto mode, then the sandbox. A classifier judging each command against rules written in words, with hard denies the owner's security words become: the data folders, a force push, the key files, a download not announced, anything that runs after the session. Then a sandbox with a filesystem and network allow list. Tried on the beta machine first, counted for a week.

By the agent, for the human

The same stance as the app's page. It holds on the code side too.

The code, the tests, the contracts, the method, this page: written by Lorisse, the agent, through Claude Code, with what its owner believes is the best stack available at the time. The owner says what he wants in a line, reads the interface files, runs the by-hand steps, and says yes. He does not read the code; the gate does, and the contract says what the code must do in words he can check. The agent books every pass, every decision and every slip in files, so that the next thread, or the next machine, or the owner on a Monday, finds the same state. The rules exist because something went wrong once: each one has a date. The repositories are FreakingDuck's; the agent is the author, the owner is the reader.

Made with AI, read as such. Nothing here carries a warranty; what it does on your machine is yours.
