Lorisse · pour Claude Code

Les agents écrivent le code. Vous lisez trois pages courtes et décidez de ce qui est mergé.

Lorisse est une façon de travailler avec Claude Code, avec une extension VS Code. Les agents écrivent le code, chacun dans sa branche ; la gate, le contrôle qui lance tous les tests, dit si ça tient ; vous relisez trois pages courtes par partie au lieu du code, et rien n'est mergé sans votre accord.

Vos agents écrivent plus vite que personne ne peut lire. Lorisse vous rend le dernier mot. Que vous codiez vous-même ou que vous meniez le projet sans toucher au code, c'est vous qui décidez.

À quoi ressemble une relecture

Vous lisez une page du projet, jamais son code. Quand quelque chose vous intrigue, vous écrivez une note dans la page, sur une ligne qui commence par deux barres obliques.

Lorisse répond juste sous votre note : la question et la réponse se lisent d'un seul fil. Quand vous êtes d'accord avec la page, vous la marquez, et votre marque s'écrit sous son titre avec la date. Cette ligne est la trace de ce que vous avez approuvé.

Ce que vous obtenez

Un agent dont la mémoire survit à la session

Lorisse garde ce qu'elle apprend de vous et du projet dans de petits fichiers, au sein d'un dépôt à vous. Elle les relit au début de chaque session, vous pouvez les corriger, et git en garde l'historique.

Trois pages par partie, et vos marques dessus

Chaque partie a un README qui dit comment elle fonctionne, un CONTRACT qui liste ce qu'elle promet, et une VALIDATION qui dit comment vérifier chaque promesse à la main. Vous marquez chaque page read, ok ou to rework, et la marque porte sa date.

Des garde-fous que l'outil applique lui-même

Un hook limite l'agent à une commande par appel du shell. Les permissions sont écrites en listes et vérifiées avant d'être installées. Une partie que vous verrouillez, aucun agent ne peut la modifier.

Un lecteur dans VS Code

L'extension montre chaque page avec son état, vous dit en mots ce qui a changé depuis votre marque, et écrit vos notes et vos marques dans la page d'un clic.

Ce qu'elle ajoute à Claude Code

Claude Code vous donne le moteur : des fichiers de mémoire, des sub-agents, un shell. Lorisse y ajoute des habitudes sur lesquelles compter. Chaque partie a ses trois pages. Chaque changement passe la gate. Une partie verrouillée le reste. Et vous avez un endroit calme pour lire et pour marquer.

Rien de tout cela ne repose sur la bonne mémoire d'un agent. Les règles vivent dans des fichiers et des hooks que Claude Code exécute à chaque appel : elles tiennent aussi le jour où l'agent n'a plus envie de les suivre.

Un changement, de votre demande au merge

Prenons un changement dans un convertisseur d'unités imaginaire.

  1. Vous demandezVous dites ce que vous voulez, avec vos mots : « une température sous le zéro absolu doit être refusée ».
  2. La promesse d'abordAvant tout code, Lorisse écrit ce qui sera vrai : une nouvelle clause dans le CONTRACT de la partie, ou une clause modifiée, avec l'étape qui la vérifie.
  3. Un builder dans sa brancheUn sub-agent prend cette seule partie, dans une branche à lui, et écrit le code et ses tests.
  4. La gate dit nonLa gate lance tous les tests. L'un échoue : rien ne peut être mergé. Le builder corrige, et la gate passe au vert.
  5. Vous dites mergeLa branche rejoint la branche principale sur votre parole, jamais avant.

Votre relecture, à votre rythme

Lire est une boucle à part. Vous ouvrez le lecteur quand vous avez un quart d'heure tranquille, pas quand un agent a besoin de vous.

  1. Vous lisez ce qui a changéLe lecteur liste les pages qui ont bougé depuis votre dernière marque, et dit en mots ce qui a changé dans chacune.
  2. Vous demandez dans la pageQuelque chose vous intrigue ? Vous laissez une note à l'endroit même, et Lorisse répond juste dessous.
  3. Vous marquezRead, ok ou to rework. Votre marque s'écrit sous le titre avec sa date : c'est la trace de ce que vous avez accepté.

Là où ça s'arrête, dit franchement

Nous préférons vous le dire maintenant plutôt que vous laisser le découvrir plus tard.

  • !Une gate ne vaut que ce que valent ses tests, et ce sont les agents qui écrivent les tests. Ce ne sont donc pas eux qu'on vous demande de croire.
  • !Ce à quoi vous pouvez vous fier, c'est ce que vous lisez et ce que vous voyez : les promesses du CONTRACT, et une courte marche que vous faites à la main.
  • !Pour du code livré à d'autres, gardez votre revue de sécurité et le regard de votre expert. Lorisse ne les remplace pas ; elle les libère pour l'essentiel.
  • !Elle a été faite par une seule personne, pour les projets d'une seule personne, et c'est là qu'elle brille. Windows aujourd'hui, avec Claude Code et VS Code. macOS vient ensuite.

Par l'agent, pour l'humain

Le code, les tests, les contrats, la méthode et cette page ont été écrits par Lorisse et par les builders qu'elle lance, à travers Claude Code. Le propriétaire dit ce qu'il veut, lit les trois pages, fait les étapes à la main, et dit oui. Il ne lit pas le code : c'est la gate qui le lit, et le CONTRACT dit ce que le code doit faire avec des mots qu'il peut vérifier.

L'agent consigne dans des fichiers chaque passe, chaque décision et chaque faux pas, pour que la session suivante, une autre machine, ou le propriétaire un lundi matin retrouvent le même état. La plupart des règles existent parce que quelque chose a mal tourné un jour. L'agent est l'auteur ; le propriétaire est le lecteur.
